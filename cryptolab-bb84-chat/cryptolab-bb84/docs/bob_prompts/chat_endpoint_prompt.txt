# BOB PROMPT: Add Chat Endpoint (chat.py) with Performance Integration

## Role & Context

You are IBM Bob, my expert AI development partner. I have already built:

- A BB84 QKD educational interface with Streamlit frontend.

Now I need an **actual chat endpoint** that can be called via HTTP (e.g., from a separate client or the Streamlit app) to serve chat completions. This endpoint will:

- Accept POST requests with a prompt and optional parameters.
- Call either a real LLM (OpenAI, Anthropic, local Llama) or a simulated backend.
- Automatically record each request's latency, token usage, cost, and success/error status into the existing `ChatPerformanceCollector`.
- Support **streaming** responses (optional but recommended).
- Include basic authentication or API key protection (simple token).
- Provide health check and metrics endpoints.

## Your Task

Generate a single file **`chat.py`** that implements this endpoint using **FastAPI** (or Flask if simpler). The file must be self‑contained, runnable as `uvicorn chat:app --reload`, and integrate seamlessly with the existing `chat_api` module.

### Requirements

1. **Imports**: Use FastAPI, uvicorn, asyncio, time, and the existing `chat_api.collector` module.
2. **Environment variables**:
   - `OPENAI_API_KEY` (optional)
   - `CHAT_SIMULATION_MODE` (default true)
   - `CHAT_API_KEY` for authentication
3. **Endpoints**:
   - `POST /v1/chat/completions` – main chat endpoint. Expects JSON: `{"prompt": str, "model": str (optional), "stream": bool (optional)}`. Returns JSON or SSE stream.
   - `GET /health` – returns `{"status": "ok"}`.
   - `GET /metrics` – returns recent performance summaries (p95 latency, error rate) from the collector.

   - On each request, create a `ChatAPICall` record (timestamp, prompt length, response length, latency, success, error, tokens, cost).

   - If `CHAT_SIMULATION_MODE=true`, use a mock LLM that echoes the prompt with configurable latency (via env `SIMULATED_LATENCY_MS`).
   - Simulated token count = len(prompt) * 0.3.
6. **Real LLM support**:
   - If `OPENAI_API_KEY` is set, call `openai.ChatCompletion.acreate` (async). Include model fallback: gpt-3.5-turbo.
   - Count tokens using `tiktoken` (if available) or approximate.
7. **Error handling**:
   - Catch exceptions, record error in collector, return 500 or 4xx as appropriate.
   - Rate limiting: use `slowapi` or a simple in‑memory token bucket (limit 10 requests per second per IP).
8. **Streaming** (bonus):
   - Implement async generator that yields SSE events.
   - For real OpenAI, use their streaming API and forward chunks.
   - For simulation, yield word by word with small delays.
9. **Documentation**: Include a docstring at the top explaining how to run and configure.

### Output Format

Output the entire content of `chat.py` inside a single markdown code block. Use comments to explain key sections. Do not add extra text outside the code block.

### Integration Note
